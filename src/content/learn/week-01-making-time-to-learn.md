This is the first entry in a weekly learning log. The aim is simple: capture useful ideas while they are still connected to the questions that produced them.

## What I explored

- How explicit trade-offs make software design discussions more productive.
- How a small evaluation set can turn an AI demo into an engineering conversation.
- How writing down an open question helps separate learning from passive consumption.

## What changed my thinking

Learning becomes easier to return to when it has a trail: the original question, the example that clarified it, and the next experiment. A note does not need to be complete to be useful. It needs to be specific enough for future me—or another engineer—to pick up the thread.

## What I want to try next

Keep the next weekly note short, include one concrete example, and connect it to something I am building or maintaining. If you are exploring a similar topic, share what you found; another person’s context is often the missing part of the lesson.
